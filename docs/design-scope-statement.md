## 1. 工艺数字口径（7nm / 28nm）

### ❌ 什么不是真的

```
本项目 **没有** 用真实 7nm / 28nm PDK 做过综合或物理验证。
原因: 不流片 + 全开源路线 → 拿不到商业 PDK (工艺厂授权) 和商业工具 (DC/Genus/ICC2)。
```

### ✅ 实际做了什么

```
综合:  Yosys + NangateOpenCellLibrary (FreePDK45, 45nm 开源标准单元库)
        → cells = 真实标准单元 (NAND/INV/DFF), 面积来自 .lib 真实值
        → 不是 FPGA LUT! (Yosys 在此作为通用综合器 + abc 映射到标准单元)
物理:  OpenROAD 完整流程 (布局/CTS/布线/IR-drop) → 真实 GDS (FreePDK45)
验证:  Verilator 周期级仿真 + 端到端推理实测
```

### 📐 7nm/28nm 数字的性质

```
docs/7nm-process-params.md 和 28nm-process-params.md 中的
面积/功耗/能效/TOPS = 基于公开工艺数据的 **理论外推 (scaling model)**,
不是 PDK 实测。

用途: 架构决策参考 (如 8×8 vs 128×128 取舍), 不是流片承诺。
```

### 📏 FreePDK45 (45nm) vs 真实先进工艺的差距

```
45nm → 7nm 的差距不是线性的:
  - 物理效应 (IR-drop/EM/天线/DFM) 复杂度指数级上升
  - 标准单元库的时序/功耗模型完全不同
  - 本项目 45nm 结果 → 7nm 只能做数量级参考, 不能直接换算

结论: 本仓库所有"7nm 极限"数字请按 **理论外推参考** 理解。
```

## 2. 架构定位声明（自研闭环 vs 商用生态）

```
本项目是 全自研教学/研究闭环:
  ISA (SM-ISA) → RTL → SoC → 微内核 (纸鸢) → 应用 (贪吃蛇/MNIST)

总线: 自研轻量总线 (非 AXI/APB) —— 刻意选择, 用于自研生态自洽
时钟: 单时钟域同步设计 —— 不存在跨时钟域 (CDC) 问题
目标: 从零理解并构建整个计算栈, 不是替代商用 SoC IP
```

## 4. 验证链现状

```
✅ BF16 阵列 RTL ↔ Python 参考: 随机数据级验证 (tools/bf16_tool.py)
✅ SoC 端到端: Verilator 周期仿真 (F2, 7958 周期 MNIST 推理)
✅ 微内核: iverilog + PicoRV32 真实 SoC 仿真 (F3, 20 万周期无 trap)
✅ GDS: OpenROAD 完整 P&R (FreePDK45) — bf16_mul 504um² + 8×8 阵列 0.94mm²
❌ ISA 模拟器 ↔ RTL: P3 未完成 (最大欠账)
```

## 5. 如果目标是"可信的先进工艺数据"

```
路径 1: 商业授权 (DC/Genus + PDK) → 需要流片预算, 超出本项目范围
路径 2: 开源先进 PDK → 目前开源社区最先进可用: FreePDK45 (45nm)
路径 3: SkyWater 130nm (开源, 可流片!) → 真实流片验证, 但工艺较老
结论: 开源路线的物理验证上限 = FreePDK45 + OpenROAD (本项目已达)
```
