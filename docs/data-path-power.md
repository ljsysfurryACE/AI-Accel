# 数据通路功耗模型：8-Bank 同时读出的物理代价

> 注水点修正文档 · 2026-08-30
> 核心教训：**软件视角 np.slice 零拷贝零延迟 ≠ 物理零功耗。**
> 8 个 Bank 同时读出需要极强驱动能力，28nm 下动态功耗巨大。

---

## 1. 注水点声明（诚实修正）

**之前的错误**：功耗模型里数据通路只写"L2 SRAM 搬运 + NoC 传输"定性描述，
从未量化 **8-Bank 同时读出的位线充放电 + 驱动级动态功耗**，相当于数据免费。

**修正后结论**：
- **BF16 浮点阵列（16-bit 数据）：数据通路功耗 ≈ 计算域的 60-70%**
- BNN（1-bit 数据）：占比仅 ~5%，数据通路不是瓶颈
- **权重重读是灾难**（每拍从 SRAM 重读权重 = 计算功耗 5 倍）→ 权重必须驻留锁存

---

## 2. SRAM 位线读能量（28nm 基准）

```
工艺: 28nm, Vdd = 0.9V
深 bank: 256 行
位线电容: C_bl = 256 行 × 0.15 fF/行 ≈ 38 fF
位线摆幅: ΔV = 0.12V (感测放大器检测点, 非全摆幅!)

每 bit 读能量 = C_bl × ΔV × Vdd ≈ 4.1 fJ (裸位线)
             ×3 (感测放大 + 预充 + 行译码) ≈ 12 fJ/bit
```

### 2.1 8-Bank 同时读的驱动能力问题（用户指出）

```
8 Bank 同时读 = 128 bit 位线同时放电 (8×16bit)
每 bit 放电电流 ≈ C_bl × ΔV / t_access = 38fF × 0.12V / 0.5ns ≈ 9.1 μA
8 Bank 合计: 128 × 9.1μA ≈ 1.2 mA 瞬时尖峰 (每拍)
128×128 大阵列: 4096 bit/拍 → ~37 mA 尖峰 → IR drop 风险!

→ 驱动管必须加大 (行译码驱动 + 位线预充 + 输出驱动)
→ 面积开销 + 输入电容增大 + 时序变差
→ 这是物理代价, 不是软件能绕过的
```

## 3. 量化对比：BF16 vs BNN 数据通路占比

### 3.1 8×8 BF16 阵列 @1GHz (28nm)

```
每拍数据流:
  激活: 8 × 16bit = 128 bit 从 8 Bank 读出
  权重: 64 × 16bit = 1024 bit (驻留锁存方案: 只付时钟; 重读方案: 灾难)

功耗分解 (每拍):
  激活读出:   128 bit × 12 fJ = 1.54 pJ
  广播布线:   128 bit × 8 扇出 × 0.5fF × 0.81V² × 0.5α = 0.21 pJ
  权重锁存时钟: 1024 bit × 5 fJ = 5.1 pJ  ← 驻留方案 (不含数据翻转)
  权重 SRAM 重读: 1024 bit × 12 fJ = 12.3 nJ  ← 灾难, 禁止!

  计算域:     64 BF16 MAC × 40 fJ = 2.56 pJ
  数据通路 (权重驻留): ≈ 1.8 pJ = 计算域的 70% !!
```

### 3.2 512×512 BNN @2GHz (28nm)

```
每拍数据流:
  激活: 512 × 1bit = 512 bit (8 Bank × 64 bit)
  权重: 262144 bit 驻留锁存 (C1 设计 ✓)

功耗分解 (每拍):
  激活读出:   512 bit × 12 fJ = 6.1 pJ
  计算域:     262144 XNOR × 0.45 fJ = 118 pJ
  数据通路占比: 5.4%  ← BNN 数据 1-bit, 可忽略
```

### 3.3 结论：为什么 BF16 是数据通路杀手

```
BNN:  数据 1-bit → 数据通路/计算 = 5%
BF16: 数据 16-bit → 数据通路/计算 = 70%

数据位宽每翻倍, 数据通路功耗翻倍, 计算功耗不变
→ 浮点阵列的数据通路功耗必须进系统模型, 否则能效注水 40%+
```

## 4. 架构对策（数据通路功耗治理）

### 命门：位线读功耗占 70%

| 对策 | 效果 | 代价 |
|------|------|------|
| **激活数据流式化** (数据就地消费) | 位线读 → 寄存器直接流水, 省 1.5pJ/拍 | 需要流水结构, 跨行广播变难 |
| **双缓冲 bank** (读一写一) | 隐藏加载, 不省读功耗 | 面积 ×1.5 |
| **浅 bank** (64 行, 4 个小 bank 替代 256 深) | 位线电容 38→9.5 fF, 读能量 ×0.25 | 面积稍增, 译码简单 |
| **数据压缩** (稀疏/差分) | 翻转率 α 0.5→0.2 | 编码器开销 |
| **权重驻留锁存** (必做!) | 避免 12nJ 灾难 | F1 已实现 ✓ |

### 推荐组合 (F 系列)

```
激活: 浅 bank (64行) + 数据流式化 → 读能量 ×0.25, 占比 70%→~20%
权重: 驻留锁存 (已有) ✓
广播: 折叠布线 (列局部, 不跨全芯片)
目标: 数据通路占比 ≤ 25%
```

## 5. 修正后的能效口径（诚实版）

### F 系列 (7nm 推算, 128×128 @3GHz)

```
之前 (注水): 49 TFLOPs 峰值, 能效未含数据通路
修正:
  峰值:       49 TFLOPs
  数据通路:   -40% (70% 占比折半给浅bank优化 → 实际 ~20-35%)
  系统口径:   ~30 TFLOPs (含数据通路, 不含利用率)
  再含利用率: ~20-25 TFLOPs (真实端到端)
```

### C 系列 (28nm BNN, 4核)

```
之前: 系统 124 TOPS/W
修正: 数据通路占比 5.4% (1-bit) → 系统口径基本不变
      ~118 TOPS/W (BNN 数据通路不是瓶颈, 瓶颈在利用率/权重重载)
```
