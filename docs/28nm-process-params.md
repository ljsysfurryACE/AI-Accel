# 28nm 工艺参数基准 (流片级)

> AI-Accel C 版 · 工艺参数基准表
> 数据来源: 公开文献/行业经验 (28nm HKMG 标准单元)
> 用途: 所有面积/时序/功耗评估必须用本表折算, 禁止纸面乐观

## 1. 核心工艺参数

| 参数 | 值 | 说明 |
|------|-----|------|
| NAND2 面积 (GE) | **0.5 μm²** | 标准单元面积基准 |
| 工艺特征时间 τ | **15 ps** | FO4 反相器延迟 |
| 逻辑密度 | ~400-500万门/mm² | 理论值 |
| 布图利用率 | **70%** | 布局布线真实利用率 (留布线通道) |
| Vdd (HPC) | 0.9V | 可 DVFS 至 0.75V |
| 6T SRAM bit | **0.12-0.15 μm²** | 高密度 SRAM 位单元 |
| DFF 等效 | ~4.5 GE | 含时钟引脚/内部逻辑 |
| 动态功耗标定 | ~0.1-0.15 μW/GE/GHz | 10-15% 翻转率 (A7 28nm 实测标定) |
| FF 时钟电容 | ~0.7 fF | 含时钟树负载 |

## 2. 折算规则 (强制)

```
面积:   GE总数 × 0.5μm² / 0.70 (布图利用率)
时序:   每 FO4 = 15ps, 2GHz 周期 = 33 FO4
功耗:   GE × 0.12μW/GE/GHz × 频率GHz (动态)
        FF × 0.7fF × V² × f (时钟树)
```

## 3. C1 核 (512×512) 流片级评估

### 3.1 原始方案 (权重 DFF + popcount 循环加法)

```
GE:      组合 10.6M + FF 7.5M = 18.0M GE
面积:    12.9 mm² (布图后)
功耗:    组合 0.72W + FF 时钟 0.94W = 1.66W/核
4核系统: ~7.6W
时序:    popcount 循环加法 24 FO4 → 超预算 ❌
```

### 3.2 流片级优化方案

| 优化 | 效果 |
|------|------|
| 权重 DFF → 6T SRAM | 0.59 → 0.039 mm², FF 时钟 -0.15W/核 |
| popcount 树形化 (拆两级) | 24 → 8 FO4/级 ✅ 2GHz 可收敛 |
| 512×512 → 256×256×4 | 同算力 (524 TOPS), 面积相近, 布线/时序更优 |

### 3.3 结论

- **512×512 单大核在真实工艺下不划算** (12.9mm², FF 时钟爆炸)
- **256×256 × 4 核** 是更优解: 同样 524 TOPS, 面积 ~13mm², 时序余量更大
- 权重必须 SRAM 化 (DFF 存权重是面积/功耗双杀)

## 4. 能效双口径 (重要! 避免混淆)

**两个能效数字, 口径完全不同:**

| 口径 | 计算 | 值 | 假设 |
|------|------|-----|------|
| **峰值 (单核理想)** | 524 TOPS ÷ 1.66W | **315 TOPS/W** | 阵列全满+数据免费+利用率100% |
| **系统 (4核真实)** | 0.94 POPS ÷ 7.6W | **124 TOPS/W** | 利用率57%+权重重载+控制域功耗 |

**315 → 124 的损耗分解:**
```
315 单核峰值
 → ×4 核并行 (2.1 POPS / 6.6W) = 不变
 → 利用率 57% (FC/池化时 BNN 空转)
 → 权重重载 85% + 流水气泡 92%
 → +控制域 1W (CPU/调度/L2/NoC)
= 124 系统口径
```

> ⚠️ **验收只认系统口径 (124 起, 优化目标 ≥200)**。峰值数字仅供宣传, 不参与验收。

## 4. 系统能效修正 (用流片级数据)

```
C1 原始方案: 0.94 POPS / 7.6W = 124 TOPS/W (系统口径)
优化方向:   SRAM 权重 + 树形 popcount + 多小核 → 目标 ≥200 TOPS/W
```

> ⚠️ 本表所有数字取代之前手算乐观值。后续版本评估一律按此基准。
